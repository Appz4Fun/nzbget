## Choose a bounded conversion investigation

- Start with immutable optimized source, objects, and binary identity. Function-scoped `llvm-objdump` symbol/disassembly inspection can establish generated calls and instruction choices without running the workload; it cannot establish execution frequency or speedup.
- If allocation/copy or instruction attribution would resolve a decision, propose a separately admitted userspace Valgrind experiment. Callgrind reports instruction/call counts; DHAT heap and copy modes are separate investigations. Confirm available tooling, supported ISA and matching debug symbols, preserve native controls, and bound fixture/time/output. Instrumented elapsed time is not native latency; copy interception need not capture every inlined move.
- Use deterministic C++/Rust differential fixtures before timing. Compare bytes, consumed/produced lengths, failure/partial-output and ownership behavior. Structure-aware `cargo-fuzz` campaigns can reach validated packet/parser interiors; proptest failure persistence retains minimized cases. The research packet did not install or execute these future scoped validation options.
- Mixed sanitizer claims require actual Rust and C++ objects plus a compatible runtime to be instrumented. A C++ sanitizer harness linked to ordinary Rust Release objects does not establish Rust sanitizer coverage. Miri applies to pure Rust unsafe/arithmetic/lifetime contracts, not actual external C++ execution. Preserve PAR main_valid and existing malformed-stop semantics in the real oracle.
- Record output work separately: formatting/output calls, initialized/copied bytes, allocated blocks and owned fallback/destruction. Compare current production C++ and clearly labeled algorithm-equivalent optimized C++ rather than attributing changed work to language choice. Criterion timing-loop setup/destruction choices change the measured boundary; its noise threshold is not formal equivalence proof.
- Predeclare practical absolute and relative effect bounds and a finite qualification budget. Preserve independent build/process levels; repeated inner iterations are not independent trials. Classify unresolved intervals as inconclusive. Workload weighting needs observed frequencies or transparent sensitivity ranges and must not conceal a critical-case regression.
- Hardware/progress causal tools such as Coz, samply/perf and rr are not workarounds for denied perf access. Check permissions, CPU/PMU/platform and workload requirements; never tune host permissions automatically. ReproZip packages dependencies for re-execution. It does not provide deterministic instruction replay or native timing control.
- PGO, cross-language LTO and CXX architecture changes need a concrete measured or ownership-maintenance reason. PGO requires representative training and separate assessment inputs; Rust/C++ linker-plugin LTO requires compatible LLVM tooling and participating objects. None is a drop-in performance qualification or general dependency-installation approval.
